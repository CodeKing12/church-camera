Set up the laptop

The receiving end. About twenty minutes, done once per laptop.

Download church-laptop.zip

30 MB · Windows · no USB drive needed

1Unzip it

Unzip to C:\church-stream. Not inside Downloads — some of this registers itself against a fixed path, so it should not move afterwards.

2Copy one file over by hand

The package deliberately leaves out webrtc\certs\ca.key. That is the private half of the certificate authority, and publishing it would let anyone issue certificates your phone trusts.

Get it from the laptop that already works — it is a 1.7 KB text file, so email it to yourself or drop it in Drive. Put it next to ca.crt in webrtc\certs\.

Worth the trouble. With that file present, this laptop gets a certificate signed by the authority your phone already trusts — so the phone needs nothing done to it at all. Without it, a new authority is created and every phone has to be set up again from scratch.

3Run one file

Double-click SETUP-NEW-LAPTOP.bat and click Yes on the prompts. It will:

  • clear the "downloaded from the internet" tag Windows puts on every file
  • open the firewall on all network types — church wifi is filed as Public, and the pop-up Windows shows by default only offers Private, so the phone would be blocked with no explanation
  • install Bonjour, which is what lets the phone find this laptop by name instead of by a number that changes
  • make this laptop's certificate
  • set the receiver to start at login and put the Camera status window on screen
  • print the one line to type into the phone

Nothing else needs installing. The package carries its own copy of openssl, so this laptop does not need Git or anything else.

4Point the phone at it

On the phone: Church Camera → SET → Laptop address, and type whatever the setup printed. It looks like this:

https://that-laptop-name.local:8889

Then Test. Green means reachable and trusted. Nothing else on the phone changes — not the certificate, not the home screen icon.

5Add it to Streamlabs

The camera is not a camera. It arrives over the network, so it will never show up under Video Capture Device and there is nothing to pick from a list.

Lowest delay — run webrtc\trust-ca-on-this-pc.ps1 once and restart Streamlabs, then Add Source → Browser Source:

file:///C:/church-stream/webrtc/whep-player.html

1920 × 1080, and untick Shutdown source when not visible. This keeps the picture inside WebRTC the whole way and skips a buffering step.

Simplest, and the fallback — Add Source → Media Source, untick Local File, then Input:

rtsp://127.0.0.1:8554/cam

Network buffering 1 MB, hardware decoding on, "Close file when inactive" off. Keep this one in a second scene whichever you use.

6Line the sound up

Open the sync ruler and follow what it says. Sixty seconds, once per laptop — the number is different on every machine. It gives you the Sync Offset to put on the desk audio source in Streamlabs.

It is also in the zip at sync\sync-ruler.html if the laptop is offline, along with sync\measure-sync.ps1, which takes the screenshots for you on a countdown.

Then check and leave it

  • The Camera window should read ALL GOOD while the phone is broadcasting, and Streamlabs: connected once the source exists.
  • Reboot, and confirm the receiver and the Camera window both come back on their own.

Full notes are inside the zip: CHURCH-LAPTOP.md for this, and LATENCY.md for where the delay actually goes. Setting up a phone instead? Certificate · the camera app.
